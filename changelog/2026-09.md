## 0.7.3 — 2026-09-25 — Close-reading: alternate examples and parked questions

Two fixes to [`close-reading`](../library/close-reading/SKILL.md) from the first live test.

#### Changed behavior

- Pushes no longer hint at, or list, what the article under study contains. When KB is stuck on a concept, the agent gives an **alternate example** from a different piece, then hands the question back.
- A question that has not cleared after three pushes (alternate examples included), or that KB answers "I don't know", is **parked** with its gap noted. KB is told it will come back later.
- New step before the Conclusion: each parked question is asked once more, with one push, and recorded OPEN only if it still does not clear. Mid-session records mark parked questions PARKED.

#### Evaluation

- Case 14 in [`evals/writing-workflows.md`](../evals/writing-workflows.md) now covers alternate examples and the park-and-revisit step.

## 0.7.2 — 2026-09-25 — Close-reading interrogator

### Added [`close-reading`](../library/close-reading/SKILL.md)

An on-demand writing skill for studying an article KB admired. KB gives every answer; the agent only asks, pushes when an answer lacks a *where*, *what*, and *so what*, checks claims against the text, and records KB's answers.

#### Behavior

- Two modes: **lite** (the 13–14 `[lite]` questions across all sections) and **complete** (every question in the sections KB keeps). The Conclusion is always asked last.
- Up to three pushes per question, then the answer is recorded as OPEN with its gap named.
- Ends with a close-reading record in KB's words, with a **Next question** line so complete-mode sessions can resume.

#### Registry and evaluation

- Library tier, `writing` profile, `owner-writing-workflows` registry group.
- Evaluation cases 13–15 in [`evals/writing-workflows.md`](../evals/writing-workflows.md).

## 0.7.0 — 2026-09-24 — Two-tier library, per-machine setup, and Fallow

Skills are now split into an installed tier and an on-demand `library/`, reached through `decide-skills`. Each machine installs only the profiles its user picks. New users fork the repository, run `bin/skills-sync setup` and then `setup-skills`, and pull releases with `bin/skills-sync sync`. Also adopts `fallow` and `fallow-review` for TypeScript/JavaScript.

### Per-machine skill selection, fork setup, and `setup-skills`

A new user no longer installs the whole library. They fork it, install a few profiles, and reach everything else through `decide-skills`.

#### Changed behavior

- New [`setup-skills`](../skills/setup-skills/SKILL.md) (installed, model-invoked) interviews a new user, recommends profiles, and installs them. It also adds or drops profiles later and syncs the fork with upstream.
- [`decide-skills`](../skills/decide-skills/SKILL.md) now covers every skill in the repository, not just `library/`. It offers to install a skill the user keeps reaching for. When nothing fits, it does the work plainly, recommends an upstream source from `registry.yaml` (no direct install), or offers to build a skill in the user's fork.
- New [`profiles.json`](../profiles.json) defines ten install bundles: `core` (always installed), `coding`, `deep-review`, `typescript`, `agent-ops`, `productivity`, `writing`, `business`, `video`, and `maintainer`. The first profile that lists a skill sets its section in the index.
- Skills that call other skills declare it as `metadata.requires` in frontmatter. `select` installs the requirements too. Library `metadata.group` is gone, replaced by profiles.
- `ask-kb` and the README now describe the fork route. The plugin stays as the install-everything option.

#### Tooling

- `bin/skills-sync setup`: adds the `upstream` remote, writes a `core`-only `my-skills.txt`, wires hooks, and installs.
- `bin/skills-sync select --add/--remove profile:<name>|<skill>`, with `--profiles` and `--dry-run`: edits `my-skills.txt`, resolves requirements, reports startup bytes against the budget, and relinks. `my-skills.txt` is git-ignored and specific to each machine. Without it, a machine installs `skills/` as before, so author machines are unchanged.
- `bin/skills-sync sync`: merges the latest upstream `V*` release tag (never `main`), rebuilds the generated index when it conflicts or lacks the fork's own skills, relinks, and lists new upstream skills.
- `refresh` links from either tier, following the selection. `validate` adds `P1-profile` and `R1-requires` errors and a `P2-unprofiled` warning.

#### Evaluation

- Exercised end to end in a sandbox with a fake upstream, a fork, and sandboxed agent directories: setup, select, an own skill, and an upstream release synced through an index conflict. Eval cases 9 to 12 in [`evals/skill-routing.md`](../evals/skill-routing.md) cover the agent-facing behaviour and have not been run.

### Two-tier library: installed skills and an on-demand `library/`

The library had reached 8,999 of its 9,000-byte description budget. Hiding skills with `disable-model-invocation` saved nothing, because Codex charges every installed description regardless. Occasional-use skills now live in an uninstalled `library/` tier, reached through one router.

#### Changed behavior

- 22 skills moved to `library/`: the writing, business, and HyperFrames workflows, and `continual-learning`. Agents no longer see them at startup. `/musings-reviewer` becomes `/decide-skills musings-reviewer`, or plain language that `decide-skills` matches.
- New [`decide-skills`](../skills/decide-skills/SKILL.md) (installed, model-invoked) reads a generated one-line-per-skill [index](../skills/decide-skills/references/index.md), loads exactly one library skill, and follows it. The group rules from the old writing and business routers now live in `decide-skills/references/groups/` and are read only after a skill in that group is picked.
- New [`ask-kb`](../skills/ask-kb/SKILL.md) (user-invoked) orients a new user: the two tiers, which door to use, and per-agent invocation.
- New [`skill-tiers`](../skills/skill-tiers/SKILL.md) (user-invoked) decides and performs moves between tiers: daily, called by an installed skill, or ambient stays installed.
- Removed the `writing`, `business`, `misc`, and `governance` routers, which `decide-skills` replaces. `coding` stays as the installed router.
- Coding skills, the Matt productivity skills, and `unslop` stay installed. `unslop` stays because `technical-writing` and `blast-radius` call it.

#### Tooling

- `bin/skills-sync validate` checks both tiers for layout and name uniqueness. It charges only `skills/` against the 9,000-byte total, keeps the 200-byte per-description cap in both tiers, and fails with `X1-index` when the index is stale. Installed descriptions now total 6,420 bytes.
- New `bin/skills-sync index` regenerates the index. New `bin/skills-sync tier <name> installed|library` moves a skill with `git mv` and regenerates the index. `new --library` scaffolds into the library.
- Version derivation, `release`, `doctor`, and `upstream`/`adopt` now count and locate skills in both tiers.

#### Evaluation

- Added [`evals/skill-routing.md`](../evals/skill-routing.md). Not yet run.
- Unverified: the Codex plugin cache is assumed to copy `library/` along with the plugin root, as the Claude plugin cache does. Check with a consumer install before release.

### Fallow codebase intelligence joins the coding category

Adopted [`fallow`](../skills/fallow/SKILL.md) and [`fallow-review`](../skills/fallow-review/SKILL.md)
from [fallow-rs/fallow-skills](https://github.com/fallow-rs/fallow-skills) (MIT, commit
`1dd4ea25f2db5bd7e73f21883fc3ec8fd7833a63`, version `1.2.57`) as supporting coding skills, following

#### Changed behavior

- `fallow` wraps the external `fallow` CLI for TypeScript/JavaScript static analysis: dead code,
  unused exports/deps, circular deps, duplication, complexity hotspots, architecture-boundary and

  `fallow` post-validates against the live dependency graph, rejecting hallucinated or stale anchors.
  Its optional live-feedback hooks (`.fallow-review/feed.jsonl` watch) are Claude Code only and stay
  self-fenced to that agent within the skill text; other agents skip that section.
- Both are listed under `coding/SKILL.md`'s new "Supporting skills: fallow" section, scoped to
  TypeScript/JavaScript work, alongside the existing pstack supporting skills.

#### Not adopted

- The upstream package's Claude plugin marketplace scaffolding (`.claude-plugin/`, `commands/`,
  `bin/`) does not apply to this repository's flat skill layout and was dropped.
- `agents/openai.yaml` on both skills (Codex-specific display metadata) was not vendored; per
  `policies/skill-format.md`, agent-specific integration belongs under `adapters/`, not the portable
  skill.

#### Provenance and evaluation

- Recorded in `registry.yaml` under `sources.fallow-skills` and `packages.fallow-workflows`, and in
  `THIRD_PARTY.md`.
- The library-wide description-budget check (`bin/skills-sync validate`, 9000-byte total) had only 25

  roughly twenty existing skill descriptions made room rather than loosening the budget itself.
- No evaluation cases have been added yet; that is the next step, not part of this adoption.

## 0.6.2 — 2026-09-11 — `youtube-transcript-to-prose` joins the writing category

Adopted an owner-supplied package as
[`youtube-transcript-to-prose`](../skills/youtube-transcript-to-prose/SKILL.md), the first writing
skill whose subject is someone else's words rather than Kiran's own thinking. It turns a supplied
video, podcast, lecture, or interview transcript into a faithful essay edition: connected prose that
keeps the creator's vocabulary, claim strength, sequence, and digressions while removing ads,
sponsorship reads, and transcript clutter.

### Changed behavior

- A transcript request now has a destination. Previously it would have fallen to `content-fence` or
  `cognitive-editor`, both of which develop or audit an argument the user owns; neither preserves
  another creator's sequence, and both would have produced a better essay than the source, which is
  the wrong output for this task.
- The skill states its own boundaries against the neighbouring writing skills by name rather than
  against "another prose-editing skill" in the abstract, and says why: those skills shape the user's
  writing, this one preserves someone else's. `unslop` runs afterwards only on request, and only on
  prose that is already faithful.
- The router records the phase boundary explicitly. The skill does not enter the Content Fence
  phases and takes no Prose Linter pass by default. A request to reshape, summarize, or argue from a
  transcript routes to `content-fence` instead.
- Summary is the refusal case, not a degraded mode. Asked for takeaways, the skill says that is the
  one output it does not produce rather than quietly producing one.

### Description budget

The library had 31 of 9,000 bytes free, and the supplied description was 366 — over the 200-byte
per-skill cap on its own. Funding it meant trimming elsewhere, so the trims went to the two skills
that carry `disable-model-invocation: true`: `wayfinder` (197 → 121) and
`setup-matt-pocock-skills` (180 → 123). Codex charges those descriptions against the budget even
though no model routes on them, so they are the cheapest bytes in the library to give up. Both keep
their trigger words. Library descriptions now total 8,975 of 9,000 bytes.

### Provenance and evaluation

- Owner-supplied package, recorded in [`registry.yaml`](../registry.yaml) as
  `transcript-prose-workflows`, source `youtube-transcript-to-prose-package`, status `trial`. The
  package carries no version, commit, or license, so `upstream` has nothing to diff against; a newer
  copy has to be re-inspected by hand rather than adopted mechanically.
- `SKILL.md` is the whole skill. No scripts, no references, no network access, no new permissions.
  The only tool the workflow reaches for is transcript retrieval when the user supplies a bare link,
  and it asks for the transcript rather than reconstructing the video when retrieval fails.
- The bundled `agents/openai.yaml` was not adopted, on the same grounds as `decision-navigator` in
  0.6.1: it is agent-specific policy metadata, and `policies/skill-format.md` places that under
  `adapters/`. Its `allow_implicit_invocation: true` and its four-product policy list are ChatGPT,
  Codex, API, and Atlas distribution settings, not portable skill content.
- The bundled `assets/icon.svg` was not adopted either. It existed only as the icon that
  `agents/openai.yaml` referenced, and it is a generic pencil glyph unrelated to the skill.
- Behavioral cases 9-12 added to [`evals/writing-workflows.md`](../evals/writing-workflows.md):
  transcript routing and the Content Fence boundary, fidelity under compression pressure, invented
  material and quotation boundaries, and a bare link supplied instead of a transcript.

## 0.6.1 — 2026-09-06 — Decision gates and bias controls in `decision-navigator`

Merged an owner-written decision-principles package into
[`decision-navigator`](../skills/decision-navigator/SKILL.md) rather than adding it as a second
skill. Two skills both claiming "consequential business decision to a committed action" would have
matched the same request, which `policies/skill-format.md` treats as one of them being wrong, and the
library had 11 bytes of description budget left.

### Changed behavior

- Hard gates now run **before** ordinary trade-offs: mandatory action, survival, the
  personal/business finance boundary, reversibility × liability, and opportunity cost. A gate is not
  a factor to weigh against others. An uncapped risk to solvency or payroll is rejected and
  redesigned, never justified by expected upside.
- The fast-path/full-path split became three named stages — Routine, Material, High-stakes — chosen
  by branching rules rather than a numeric score. Ties break upward when the cost of being wrong is
  asymmetric. Routine choices stop after a short check and end in their own compact six-line shape,
  so the light path terminates somewhere definite instead of improvising beside the eleven-item
  synthesis. A routine decision that produces a memo, reference class, premortem, hedge, or decision
  log is stated to be a misclassification. Without this the stage split does not hold: the escape
  hatch is one line against a long document, and the tiebreak only ever pushes upward.
- Bias handling became a process control instead of a label. The skill names only traps that
  plausibly change the decision at hand, gives the mechanism, and applies a correction; the full
  index lives in `references/bias-map.md` and is read on demand, never recited.
- The decision now ends on exactly one of seven named actions: PROCEED, SMALL BET, GET MORE
  INFORMATION, WAIT, ESCALATE, REJECT, EXIT. GET MORE INFORMATION must name the missing fact, how it
  changes the decision, and when gathering stops.
- Added a premortem, an outside-view/reference-class step before the inside story, a decision log
  written before material commitment, and a review that judges process quality separately from
  outcome quality.
- Owner defaults are stated as heuristics, not findings — including the review-and-normally-exit
  trigger at roughly 50% of a predefined bet.
- The India/MSME context moved from one paragraph to explicit checks on receivable days, payment
  reliability, working-capital requirement, statutory burden, and local execution capacity, with
  fifteen decision-type playbooks in `references/business-playbooks.md`.
- The `business` router description was trimmed by 58 bytes to fund the new trigger words. Library
  descriptions now total 8,969 of 9,000 bytes.

### Provenance and evaluation

- Owner-written, from the owner's own notes. Recorded in [`registry.yaml`](../registry.yaml) as
  `owner-decision-principles`, source `repository-owner`, status `trial`, merged into
  `decision-navigator`.
- Four reference files were adopted: `core-principles.md`, `bias-map.md`, `business-playbooks.md`,
  and `research-basis.md`. No scripts, no network access, no new permissions.
- `research-basis.md` carries an evidence filter that refuses the popular-but-unsupported versions of
  its own claims: no universal loss-aversion multiplier, no fixed social-loafing percentages, no
  blood-sugar theory of decision fatigue, no arbitrary winner's-curse discount. Its two 2024
  loss-aversion meta-analyses disagree, and the file says so rather than picking one.
- The TReDS/CPSE claim was verified independently: notified 30 June 2026, announced 10 July 2026. A
  second source was added because the PIB URL refuses automated fetches.
- The bundled `agents/openai.yaml` was not adopted. It is agent-specific policy metadata, and
  `policies/skill-format.md` places that under `adapters/`.
- Behavioral cases 10-15 added to [`evals/business-workflows.md`](../evals/business-workflows.md):
  survival gate, explicit bias check, sunk-cost continuation, mandatory change, process-vs-outcome,
  and a routine decision staying routine.

## Unreleased — Deterministic checks for AI-written code

Closed the gap between a green build and correct code. Three failure modes that survive a clean
typecheck and a passing test run are now caught by a script rather than described in prose, and the
two skills around implementation were rewritten to prevent and detect them.

### Changed behavior

- `implement` was fifteen lines, the thinnest skill in the chain and the one a mid-tier model runs.
  It now states the ticket and its user stories before coding, stops on an ambiguous business rule
  instead of guessing, works one vertical slice at a time, holds import-resolution and no-silent-catch
  rules on every slice, and lists what it did not do at the end.
- `code-review` carries a **generated-code baseline** alongside the Fowler smells. Unlike the smells,
  these are not judgement calls: each is checkable against the code or the lockfile, so a hit is a
  finding. Standards gets phantom dependency, silent catch, and lying comment; Spec gets unhandled
  named edge cases and tests that pass by construction.
- [`bin/agent-gates`](../bin/agent-gates) is a new self-contained checker: `check`, `install`, and
  `self-test`. `install` copies it into a project as `scripts/agent-gates` with a pre-commit hook, so
  the gate survives this library moving. Typecheck and tests were deliberately left out of the hook:
  both are slow, and a slow hook gets bypassed, which costs more than it catches.
- `swarm` gained a **Before you fan out** gate. Fanning out to write code is now ruled out; fanning
  out to review, explore, or race is the sanctioned use. Phase C is named as the cross-check that
  earns the coordination cost rather than a formatting step.
- `reflect` step 4 inverted. A script-enforceable lesson used to go to Backlog, where it was lost
  because the script never got written and the rule never got added. It now carries forward as a
  proposed `check:` item. The synthesizer reference, its routing table, and steps 5 and 6 moved with
  it; inverting step 4 alone would have had no effect, since the synthesizer runs first.
- A dangling pointer to a non-existent `encode-lessons-in-structure` skill was removed from
  `reflect`. Two files still carry it and are logged, not fixed.

### Provenance and evaluation

- Sourced from *The New SDLC With Vibe Coding* (Google, May 2026), *Towards a Science of Scaling
  Agent Systems* (arXiv 2512.08296), Anthropic's *Building Effective Agents*, and Domino's agentic
  engineering playbook. The reasoning, what was declined, and why is in
  [`docs/decisions/agentic-engineering-adoption.md`](../docs/decisions/agentic-engineering-adoption.md).
- `swarm`'s table is presented as an ordering of shapes, not a prediction. The study matched total
  token budget across topologies, so its penalty is larger than this harness would see.
- Behavioral cases are in [`evals/workflow-gates.md`](../evals/workflow-gates.md).
- `agent-gates` was measured against two of this owner's repositories during the build. Findings fell
  from 2305 to 6 on one and 849 to 11 on the other as five false-positive classes were fixed; the
  remainder were checked by hand and are true positives. Its `self-test` doubles as the regression
  suite: every construct in its clean fixture once produced a false positive on real code.
- `prototype` needed no change. Its existing rules 1 and 6 already keep prototype code off main.

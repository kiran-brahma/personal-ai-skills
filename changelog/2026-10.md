### Updated Matt Pocock skills to v1.3.1

Merged from [mattpocock/skills](https://github.com/mattpocock/skills/releases/tag/v1.3.1) at commit `24fe0ef7737efae15c87225755e9f6f5965e4888` (MIT) with `bin/skills-sync adopt`. Upstream `main` at `4588b32` has no further changes in the vendored folders.

#### Changed behavior

- **Domain doc renamed `CONTEXT.md` → `GLOSSARY.md`** (and `CONTEXT-MAP.md` → `GLOSSARY-MAP.md`) in every skill that reads or writes it: `domain-modeling`, `grill-with-docs`, `improve-codebase-architecture`, `setup-matt-pocock-skills`, `triage`, `tdd`, `diagnosing-bugs`, `ask-matt`, `codebase-design`, `wait-what`, and the local `goldilocks-review`. Skills no longer look for `CONTEXT.md`. Run `git mv CONTEXT.md GLOSSARY.md` in existing projects.
- [`domain-modeling`](../skills/domain-modeling/SKILL.md) triggers on discussing codebase terminology or editing a `GLOSSARY.md` or ADR directly. `CONTEXT-FORMAT.md` is now `GLOSSARY-FORMAT.md`.
- [`diagnosing-bugs`](../skills/diagnosing-bugs/SKILL.md) no longer hands off to `improve-codebase-architecture` from its post-mortem. Phase 6 is cleanup only.
- [`ask-matt`](../skills/ask-matt/SKILL.md) routes to `implement-spec` as the parallel alternative to per-ticket `implement`, to `pr` for PR bodies, and to `retro` as the last step of the main flow. The conflict was resolved by keeping upstream's structure and both local gates: `goldilocks-review` after `to-spec`, and `thermos` before `code-review` on a major change.

#### Added (installed tier, because `ask-matt` names them)

- [`implement-spec`](../skills/implement-spec/SKILL.md): implement a whole spec in one run, with implementer subagents in parallel worktrees across the ticket graph's frontier, merged onto one integration branch. User-invoked. Local adaptation: on a major change it stops and asks the user to run `/thermos` before `code-review`, matching `implement`.
- [`pr`](../skills/pr/SKILL.md): PR body template: smallest visual summary, before/after evidence, merge-danger call. Model-invoked, so it fires whenever the agent writes a PR. Credits Dex Horthy's `show-me` in `CREDITS.md`.
- [`retro`](../skills/retro/SKILL.md): suggest environment changes (checks, standards, steering files, tooling) after a coding session. User-invoked. Overlaps with pstack `reflect` and `correct`. `retro` reviews one session, `reflect` mines rules from feedback, and `correct` fixes repeated mistake classes repo-wide.

#### Removed

- `resolving-merge-conflicts`, following upstream. Agents resolve conflicts without a dedicated skill. References in `setup-skills`, `bin/skills-sync sync`, and `evals/skill-routing.md` now say to resolve by tracing both sides' intent.

### Added pstack [`correct`](../library/correct/SKILL.md) and [`principle-test-behavior-not-implementation`](../library/principle-test-behavior-not-implementation/SKILL.md)

Vendored from [cursor/plugins](https://github.com/cursor/plugins/tree/main/pstack) at commit `2cbf58508f40de470d7490b55c51d71241928fa2` (pstack 0.15.13, MIT).

#### Behavior

- On demand only, in `library/`, reached through `decide-skills`. Both are user-invoked.
- `correct` groups the mistakes agents repeat in a repo into classes (seen twice), fixes each at the highest level that works (architecture, then types, then a lint, then a test, docs last), proves each check fails on a real past mistake, and keeps a rule-to-enforcer table in the agent instruction file.
- `principle-test-behavior-not-implementation` rejects any test that would still pass if every import returned `undefined`, and names five such shapes along with their fixes.

#### Adaptations

- Shorter descriptions for the trigger budget, with the pstack portability note added. Bodies are verbatim upstream.

#### Registry and evaluation

- New `cursor-pstack-0.15` source and `pstack-correctness` package. The main `cursor-pstack` pin stays at `efa2a53` because its 12 changed skills have not been reviewed. Fold the two sources together once they are.
- `correct` is in the `agent-ops` profile and the principle is in `coding`. Evaluation cases are in [`evals/workflow-gates.md`](../evals/workflow-gates.md).

### Fixed `bin/skills-sync upstream` and `adopt` on binary files

- Both decoded upstream files as UTF-8 text, so `upstream` crashed with `UnicodeDecodeError` on a binary file in a vendored skill (first seen on `heygen-hyperframes`), and `adopt` would have done the same. Files are now read as raw bytes. `adopt` replaces a binary that is unchanged locally with upstream's copy, and lists one that was also edited locally as needing a decision instead of merging it line by line.

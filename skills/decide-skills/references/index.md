# Skill index

Generated by `bin/skills-sync index` from every skill in the repository and `profiles.json`. Do not edit by hand.

One line per skill: name, trigger contract, path from the repository root. Sections are install profiles.
`[explicit]` marks a gate: run it only when the user asked for it by name or intent.

## core
Entry points: route to any skill, orient, set up. Always installed.

- `ask-kb` [explicit]: Ask which skill or flow fits your situation in this library, what is installed versus on demand, and how to invoke each. A guide to the library. `skills/ask-kb/SKILL.md`
- `decide-skills`: Find and run the right skill from this library when no installed one fits, or recommend adding or building one. For writing, business, video, uninstalled skills. `skills/decide-skills/SKILL.md`
- `setup-skills`: Choose which skills this machine installs: first-run interview, add or drop profiles, sync a fork with upstream. Not for changing repo defaults, use skill-tiers. `skills/setup-skills/SKILL.md`

## deep-review
Heavier lenses for big or risky changes: major-change review, blast radius, design comparison.

- `architect` [explicit]: Sketch types, signatures, and module structure before code, staying in the loop during implementation. Use when jumping to code locks in the wrong shape. `skills/architect/SKILL.md`
- `arena` [explicit]: Spawn parallel candidates at one task, pick a base, graft in the losers' strongest parts. Use when a single attempt would lock in the wrong shape. `skills/arena/SKILL.md`
- `blast-radius` [explicit]: Find what a change could break beyond its diff, and prove safety by running real code. Use for 'what could this break' or a diff you don't trust. `skills/blast-radius/SKILL.md`
- `how` [explicit]: How does X work: code walkthroughs, runtime flow, subsystem architecture, and placement questions ('where should this live'). Use why for motivation. `skills/how/SKILL.md`
- `interrogate` [explicit]: Adversarial multi-model review: reviewers challenge changes from independent angles. Use for 'stress test', 'find blind spots', 'tear apart'. `skills/interrogate/SKILL.md`
- `thermo-nuclear-code-quality-review` [explicit]: Strict maintainability and structural-simplicity review of changed code in a major change: deep modules, fewer concepts, deletion opportunities. `skills/thermo-nuclear-code-quality-review/SKILL.md`
- `thermo-nuclear-review` [explicit]: Audit added or modified code for correctness, breakage, security, developer-experience regressions, and feature-gate leaks during a major-change review. `skills/thermo-nuclear-review/SKILL.md`
- `thermos` [explicit]: Run deep correctness/security/devex and maintainability reviews for a major change, then synthesize findings before the normal code review. `skills/thermos/SKILL.md`
- `why` [explicit]: Design rationale and history: 'why does X work this way', 'why we picked Y', regressions, postmortems. Cites evidence sources. Use how for runtime behavior. `skills/why/SKILL.md`

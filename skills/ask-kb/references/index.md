# Skill catalogue

Generated by `bin/skills-sync index` from every skill and its theme in `profiles.json`. Do not edit by hand.

One line per skill: name, trigger contract, path from the repository root. Sections are primary themes.
`[explicit]` marks a gate: run it only when the user asked for it by name or intent.

## Coding
Software development, maintenance, and engineering workflows.

- `architect` [explicit]: Sketch types, signatures, and module structure before code, staying in the loop during implementation. Use when jumping to code locks in the wrong shape. `library/architect/SKILL.md`
- `arena` [explicit]: Spawn parallel candidates at one task, pick a base, graft in the losers' strongest parts. Use when a single attempt would lock in the wrong shape. `library/arena/SKILL.md`
- `ask-matt` [explicit]: Ask which skill or flow fits your situation. A router over the skills in this repo. `library/ask-matt/SKILL.md`
- `blast-radius` [explicit]: Find what a change could break beyond its diff, and prove safety by running real code. Use for 'what could this break' or a diff you don't trust. `library/blast-radius/SKILL.md`
- `code-review`: Review changes since a commit, branch, tag, or merge-base: repo standards and spec match. Use for 'review this branch/PR' or 'review since X'. `library/code-review/SKILL.md`
- `codebase-design`: Deep-module vocabulary for designing or improving a module interface, placing a seam, or making code more testable. `library/codebase-design/SKILL.md`
- `coding`: Route software-development work to the most relevant focused skill: planning, implementation, debugging, review, testing, release. `library/coding/SKILL.md`
- `correct` [explicit]: Find mistakes agents keep repeating in a repo and make each impossible: architecture, then types, then a lint naming the fix, then a test, docs last. Rerun after each correction. `library/correct/SKILL.md`
- `create-verification-skill` [explicit]: Generate a project-local skill that drives the app like a user, any language or framework. Use when a project has no scripted way to prove behavior. `library/create-verification-skill/SKILL.md`

- `domain-modeling`: Build and sharpen a project's domain model. Use when discussing codebase terminology, writing or editing a GLOSSARY.md, or recording or editing an ADR. `library/domain-modeling/SKILL.md`
- `fallow`: Static analysis for TypeScript/JavaScript via the fallow CLI. Find dead code, duplication, circular deps, complexity hotspots, architecture drift. Not for type checking or linting. `library/fallow/SKILL.md`
- `fallow-review`: Graph-validated PR/diff review for TypeScript/JavaScript via fallow. Subtracts dead-code noise, surfaces structural decisions (API, coupling, deps). Not a CI gate, use fallow's audit command for that. `library/fallow-review/SKILL.md`

- `how` [explicit]: How does X work: code walkthroughs, runtime flow, subsystem architecture, and placement questions ('where should this live'). Use why for motivation. `library/how/SKILL.md`

- `implement-spec` [explicit]: Implement the result of /to-spec and /to-tickets in code. `library/implement-spec/SKILL.md`

## Writing
Creating, editing, reviewing, and understanding prose and documents.
Routing notes: `skills/ask-kb/references/groups/writing.md`

- `book-reference-extractor`: Build source-faithful book documents from highlights or notes: author reconstruction, durable reference, reader response, Book Memo. Interviews the reader first. `library/book-reference-extractor/SKILL.md`
- `business-blog-post-generator`: Draft an evidence-led company blog post: audit existing content, find topic gaps, interview the owner. Not for personal essays or autonomous publishing. `library/business-blog-post-generator/SKILL.md`
- `close-reading`: Interrogate KB's close reading of an article they admired: KB answers, the agent only asks and pushes back. Lite or complete mode. Not for auditing drafts, use cognitive-editor. `library/close-reading/SKILL.md`
- `cognitive-editor`: Editorial audit of any writing, KB's drafts or an unfamiliar piece. Use for 'audit this', 'check this draft', or when KB pastes writing for feedback. `library/cognitive-editor/SKILL.md`
- `content-fence`: KB's essay-development workflows, no ghostwriting: thinking grills, Thinking Essay development, reader reconstruction, reader-response audits, prose linting. `library/content-fence/SKILL.md`
- `musings-reviewer`: Review KB's daily musing (one atomic idea, 300-word cap) for atomicity, argument, and prose. Not for essays or blog drafts, use cognitive-editor. `library/musings-reviewer/SKILL.md`
- `technical-writing` [explicit]: Standard for writing or reviewing docs, RFCs, readmes, PR descriptions, and commit messages: Diataxis, Google style, STE, Global English. `library/technical-writing/SKILL.md`
- `unslop`: Final pass removing AI-writing patterns from long-form prose, preserving meaning, voice, quotations. Use when writing sounds AI-generated. `library/unslop/SKILL.md`
- `writing-for-agents`: Writing documents for agents. Use when creating or editing skills, or modifying AGENTS.md or CLAUDE.md. `library/writing-for-agents/SKILL.md`
- `youtube-transcript-to-prose`: Turn a YouTube, podcast, lecture, or interview transcript into faithful essay prose, ads and clutter removed. Not a summary or a new essay. `library/youtube-transcript-to-prose/SKILL.md`
